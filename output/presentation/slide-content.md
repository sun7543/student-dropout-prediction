# Student Dropout Prediction — เนื้อหาสไลด์

## 1. Student Dropout Prediction

ระบบทำนายความเสี่ยงการออกกลางคันของนักศึกษา

- คุณานนท์ มาลยานนท์ 6810450807
- กฤตภาส สุขประสงค์ 6810450718
- โครงงาน Machine Learning

## 2. ที่มาและความสำคัญ

การเรียน พฤติกรรม และสภาพแวดล้อมของนักศึกษาเป็นข้อมูลที่ใช้ศึกษาความเสี่ยงร่วมกันได้

- พัฒนาต้นแบบเพื่อช่วยคัดกรองนักศึกษาที่อาจต้องการการดูแล
- รวมข้อมูลหลายด้านไว้ในแบบจำลองเดียว
- ผลทำนายใช้ประกอบการพิจารณาและติดตามเพิ่มเติม

## 3. วัตถุประสงค์และผู้ใช้งาน

สร้างระบบจำแนกความเสี่ยงพร้อมหน้าจอใช้งาน

- เปรียบเทียบ Logistic Regression, Decision Tree และ Random Forest
- ประเมินผลกับข้อมูลที่แยกไว้สำหรับทดสอบ
- ผู้ใช้เป้าหมาย: อาจารย์ที่ปรึกษาและเจ้าหน้าที่ดูแลนักศึกษา

## 4. ภาพรวมชุดข้อมูล

ใช้ไฟล์ data/raw/dataset.csv ในโปรเจกต์

- 800 แถว 25 คอลัมน์ก่อนคัดเลือกตัวแปร
- นักศึกษาอายุ 17–25 ปี และชั้นปี 1–4
- เลือกใช้ 17 input features และเป้าหมาย Dropout_Risk
- ยังไม่มีลิงก์ผู้เผยแพร่ต้นทางในเอกสารโปรเจกต์

## 5. กลุ่มข้อมูลนำเข้า

17 ตัวแปรครอบคลุมข้อมูลพื้นฐาน การเรียน และสภาพแวดล้อม

- พื้นฐาน: อายุ ชั้นปี สาขา ที่พัก
- การเรียน: การเข้าเรียน ชั่วโมงอ่านหนังสือ GPA วิชาค้าง
- พฤติกรรมและเศรษฐกิจ: เวลาใช้หน้าจอ งานพิเศษ รายได้ครอบครัว
- การสนับสนุน: ความเครียดการเงิน ครอบครัว ความเครียด ความกังวล แรงจูงใจ การเข้าถึงคำปรึกษา

## 6. สิ่งที่ต้องการทำนาย

Binary Classification โดยมี Dropout_Risk เป็น label ของชุดข้อมูล

- Yes: กลุ่มที่ชุดข้อมูลระบุว่ามีความเสี่ยง 437 คน (54.63%)
- No: กลุ่มที่ชุดข้อมูลระบุว่าไม่มีความเสี่ยง 363 คน (45.38%)
- กราฟแท่งสองกลุ่มใช้จำนวน 437 และ 363
- label ความเสี่ยงไม่ใช่หลักฐานยืนยันการออกกลางคันจริง

## 7. คุณภาพของข้อมูล

ตรวจค่าที่หายไปและข้อมูลซ้ำก่อนสร้างโมเดล

- ไม่พบแถวซ้ำหรือ Student_ID ซ้ำ
- ค่าที่หายไป: Attendance 51, Stress 49, Family Support 44, Financial Stress 43, Motivation 41 แถว
- กราฟแท่งแสดงจำนวน missing ของตัวแปรทั้งห้านี้
- กำหนดวิธีเติมค่าไว้ใน Pipeline

## 8. การคัดเลือกตัวแปร

ลดจาก 24 ตัวแปรที่ไม่ใช่เป้าหมาย เหลือ 17 ตัวแปร

- ตัด Student_ID เพราะเป็นรหัสเฉพาะบุคคล
- ตัด Gender เพื่อลดการใช้ข้อมูลเพศโดยตรง แต่ยังไม่ได้พิสูจน์ว่าโมเดลปราศจาก bias
- ตัด Burnout_Level ซึ่งโปรเจกต์ถือเป็นอีกผลลัพธ์หนึ่ง
- ตัด Sleep, Exercise, Social Activity และ Peer Pressure เพื่อลดภาระการกรอก

## 9. การแบ่ง Train / Validation / Test

แบ่งข้อมูลก่อน fit preprocessing และใช้ stratify ตาม label

- Train: 560 คน (70%)
- Validation: 120 คน (15%)
- Test: 120 คน (15%)
- กำหนด random_state = 42; ใช้ Validation เลือกโมเดล และเก็บ Test ประเมินผลสุดท้าย

## 10. การเตรียมคุณลักษณะ

จัดการข้อมูลตามชนิดของตัวแปร

- ตัวเลข: เติม mean และใช้ StandardScaler
- Backlogs: เติม median แล้ว scale
- สาขา ที่พัก งานพิเศษ: เติม Unknown และ One-hot encoding
- รายได้: Ordinal encoding; การเข้าถึงคำปรึกษา: No=0, Yes=1

## 11. Pipeline และการป้องกัน Data Leakage

รวม preprocessing และ model เพื่อให้ fit ใหม่ภายในแต่ละ fold

- 17 raw features กลายเป็น 28 features หลัง preprocessing บน Train
- ไม่เหลือ NaN หลัง preprocessing
- Cross-validation เรียนรู้ค่าที่ใช้เติมและ scale จาก training fold เท่านั้น
- บันทึก Pipeline ทั้งชุดเป็นไฟล์ joblib สำหรับแอป

## 12. ผลโมเดลเบื้องต้น

เปรียบเทียบ Train Accuracy และ Validation Accuracy ก่อน tuning

- ตาราง/กราฟคู่: Logistic Regression 73.39% / 65.83%
- Decision Tree 100.00% / 59.17%
- Random Forest 100.00% / 60.83%
- โมเดลต้นไม้มีช่องว่าง Train–Validation สูง จึงต้องควบคุมความซับซ้อน

## 13. Hyperparameter Tuning

ใช้ RandomizedSearchCV แบบ 5-fold บน Train และ scoring='accuracy'

- Logistic Regression: ทดลอง C 6 ค่า; ดีที่สุด C=0.01, CV Accuracy 71.25%
- Decision Tree: 30 ชุด; depth=10, min_samples_leaf=10, min_samples_split=2; CV 63.21%
- Random Forest: 40 ชุด; 100 trees, depth=5, min_samples_split=10, min_samples_leaf=1, max_features=sqrt; CV 71.07%
- CV score เป็นผลบน Train folds ไม่ใช่ Test score

## 14. การเลือกโมเดลสุดท้าย

เลือก configuration จาก Validation Accuracy

- กราฟเรียงจากสูงลงต่ำ: Tuned Logistic Regression 68.33%, Tuned Random Forest 67.50%, Baseline Logistic Regression 65.83%, Tuned Decision Tree 59.17%
- เลือก Tuned Logistic Regression ที่ C=0.01
- fit ใหม่ด้วย Train + Validation รวม 680 คน
- ประเมิน Test 120 คนหลังเลือก configuration

## 15. ผลประเมินบน Test

Logistic Regression ทำนายถูก 76 จาก 120 คน

- Accuracy 63.33%
- กลุ่ม Yes: Precision 64.38%, Recall 72.31%, F1-score 68.12%
- Confusion Matrix: แถว Actual No/Yes; คอลัมน์ Predicted No/Yes; [[29,26],[18,47]]
- กลุ่มเสี่ยงที่พลาด 18 คน; กลุ่ม No ที่ถูกเตือนเป็น Yes 26 คน

## 16. ข้อจำกัดของผลลัพธ์

ผลทดสอบสะท้อนความสามารถของต้นแบบในข้อมูลชุดนี้

- Test มีเพียง 120 คน และยังไม่มีการยืนยันกับข้อมูลนักศึกษาจากสถาบันจริง
- การเตือนผิด 26 คนและพลาดกลุ่ม Yes 18 คนยังมีผลต่อการใช้งาน
- การตัด Gender ออกไม่เท่ากับการตรวจความเป็นธรรมครบถ้วน
- ควรใช้เพื่อช่วยคัดกรองและสนับสนุน ไม่ใช้ตัดสินสิทธิของนักศึกษาโดยลำพัง

## 17. การใช้งาน Streamlit

หน้าเว็บรับข้อมูล 17 ตัวแปรและแสดงผล Yes หรือ No

- 1. กรอกข้อมูลพื้นฐาน การเรียน และสภาพแวดล้อม
- 2. กรอก Previous GPA ในช่วง 0–4
- 3. กด Predict เพื่อดู Predicted dropout risk
- เบื้องหลังแปลง GPA ด้วย GPA × 2.5 เช่น 2.80 เป็น 7.00 ก่อนเข้า Pipeline; นี่คือการเทียบสเกลเชิงเส้น

## 18. แนวทางพัฒนาต่อ

ปรับปรุงคุณภาพข้อมูลและการประเมินก่อนใช้งานจริง

- ตรวจสอบแหล่งข้อมูลและความหมายของ label ให้ชัดเจน
- เพิ่มข้อมูลและทดสอบกับนักศึกษานอกชุดฝึก
- เลือก threshold ให้สอดคล้องกับต้นทุนของการพลาดและการเตือนผิด
- ตรวจ calibration ความเป็นธรรม และความเหมาะสมของการเทียบ GPA
